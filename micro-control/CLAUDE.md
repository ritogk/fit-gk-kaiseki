# CLAUDE.md — 車両灯火ライブ制御システム (micro-control)

MIDIコントローラーで実車の灯火を「演奏」するライブシステム。現在CH1(フォグ)の調光制御が実車で動作確認済み。このディレクトリでは統合ファームウェアを開発する。

**最終目標**: 自作アプリ/Webから高速に、最終的にはMIDIキーボードから、フォグ・ロービーム・ハイビーム・ウィンカー左右・ポジション(車幅)を細かく制御する。将来的には灯火以外の系統にも拡張する。

## 確定済みハードウェア構成

```
[操作系] → ESP32-S3 → BTS7960 → フォグランプ
                ↑
        車載バッテリー → ヒューズブロック(ATO/ATC)
```

- **マイコン**: Freenove ESP32-S3 Board Lite (FNK0099, ESP32-S3-WROOM, 8MB PSRAM)
  - USB-Cが2つ: UART側(CH343, 書き込み/シリアル用) / OTG側(ネイティブUSB, MIDI機器接続用)
- **パワー段**: BTS7960モジュール(IBT-2)。片方向構成で使用
- **車両**: ホンダ フィット GK系
- **灯火(CH1)**: ハロゲンフォグ。純正ヒューズ15A。バルブはH8(35W=約2.9A/灯)の可能性が高い(刻印未確認)
- **電源**: 車載12Vバッテリー → 5Aヒューズ(机上テスト時) → B+

### ピンアサイン(変更禁止)

| ESP32 | 接続先 | 役割 |
|---|---|---|
| GPIO4 | BTS7960 RPWM | PWM出力(明るさ) |
| GPIO5 | BTS7960 R_EN + L_EN(束ね) | 出力許可。**起動時LOW必須** |
| GPIO2 | BTS7960 R_IS(配線のみ、未実装) | 電流センス(将来の球切れ検知用) |
| 3V3 | BTS7960 VCC | ロジック電源 |
| GND | BTS7960 GND → GNDバスバー | 一点集約 |
| GPIO6/7/8 | (予約) | 将来のCH2(ヘッドライト)/CH3・4(ウィンカー) |
| GPIO9 | (予約) | 将来の系統切替リレー駆動 |

BTS7960側: LPWM→GND固定、L_IS開放。**RPWM/LPWM同時HIGHは貫通短絡で破損(絶対禁止)**。

## 検証済みの事実

- M+/M−電圧テスト合格: バッテリー12.6V時、体感30%指定→7V、体感100%(80%cap)→10V。ガンマ補正込みの計算値と一致
- 実フォグでの点灯・調光成功
- ソフトスタート(300ms)が実負荷で機能

## 灯火制御の確定パラメータ(ハロゲン)

```cpp
PWM_FREQ = 200;      // Hz。ハロゲンは熱慣性で十分。LED化したら1000以上
PWM_RES  = 12;       // bit (duty 0-4095)
GAMMA    = 0.5;      // 体感リニア化。ハロゲン=0.5 / LED=2.2
RAMP_MS  = 300;      // ソフトスタート。ハロゲンでは突入電流対策として必須
MAX_DUTY_PCT = 100;  // バッテリー電源時。5A級ACアダプタ時は80
```

- 明るさは「体感%」(0-100)で保持し、`duty = (pct/100)^GAMMA * 4095` で変換後、MAX_DUTY_PCTでcap
- 減光はランプアップの2倍速

## 安全要件(全ファームウェア共通・削除禁止)

1. `setup()` 冒頭で `PIN_EN` を OUTPUT/LOW に初期化 → 全準備完了後にHIGH(起動時の誤点灯防止)
2. 起動時の明るさは常に0%
3. ハロゲン運用中はソフトスタート(RAMP_MS>=300)を維持。RAMP_MS=0 の即応モードはLED化後に解禁
4. MAX_DUTY_PCT による上限capを維持(電源保護)

## 次に実装するもの: 統合ファームウェア (`firmware/micro_control/`)

### 要求

1. **入力3系統の統合**: USB MIDI / シリアルキー / Web(WiFi) を同時に受け付け、last-writer-wins で明るさに反映
2. **遅延の優先順位**: ライブの主操作はUSB MIDI(約1ms)。Webはプリセット・リハ・モニタ用のサブ系統。HTTPをWebSocketに置き換えて双方向化(状態を全クライアントに同期)するのが望ましい
3. **アーキテクチャ**: 入力層(MIDI/Serial/Web) → 照明エンジン(体感%→ガンマ→cap→ランプ) → 出力層(LEDC) を分離。将来のマルチチャンネル化(CH1-4, 各チャンネル独立のfreq/gamma/ramp)を見据えた構造にする
4. **演出機能(第2段階)**: 点滅(周期指定)、ストロボ、フェードイン/アウト、パターンのプリセット保存。ウィンカー法規パターン(60-120回/分)も将来用に
5. **MIDI割り当て**: CC16(ノブ1)=明るさ, CC32(Sボタン1)=ON/OFFトグル, NoteOn=トグル(パッド系対応)。CC番号は設定で変更可能に

### 開発環境

- Arduino IDE 2.x + esp32 by Espressif v3.x(LEDC APIは `ledcAttach(pin, freq, res)` / `ledcWrite(pin, duty)` の3.x系)
- ボード: ESP32S3 Dev Module
- **USB CDC On Boot: Enabled**(ネイティブUSBポートでシリアル運用中)
- MIDI使用時のみ: **USB Mode: USB Host** + ライブラリ `ESP32_Host_MIDI`(イベントキュー方式, `midiHandler.getQueue()`, `ev.index` で既読管理)
- 開発機: Apple Silicon Mac(Rosetta 2導入済み)。ポートは /dev/cu.usbmodem*
- 注意: USB HostモードではOTGポートがシリアルにならない。書き込み/モニタはUART側(CH343)を使うこと

### テスト手順(ハード無しでも可能な範囲)

1. シリアルモニタで各キー→ログの duty 値が期待通りか
2. 実機: 灯具を外し M+/M−にテスター → 体感30%→約7V / 100%→約10V(バッテリー12.6V時)
3. 実負荷: ソフトスタートの「ふわっと点灯」目視 + 30分点灯後にBTS7960放熱板・端子を触診(50℃以下)

## 系統プラン — 最終形 (2026-08-01 追記)

| 系統 | 光源 | 制御方式 | ドライバ案 |
|---|---|---|---|
| CH1 フォグ | ハロゲン H8 35W | PWM調光 (200Hz, γ0.5, ramp300ms) | BTS7960 **(動作確認済)** |
| CH2 ロービーム | **HID** | **ON/OFFのみ。PWM調光・ストロボ禁止**(バラスト保護。点灯数秒+再点灯遅延あり) | リレー or ハイサイドスイッチ |
| CH3 ハイビーム | **LED** | PWM調光想定 (1000Hz+, γ2.2, ramp0可)。灯体内蔵ドライバとの相性は要ベンチ検証 | MOSFETモジュール |
| CH4/5 ウィンカー左/右 | 電球21W想定 | 点滅パターン主体 | MOSFETモジュール |
| CH6 ポジション/車幅 | 要確認 | PWM調光(演出) | 小型MOSFET |

- GK5では「ポジション」と「車幅灯」は同一回路の可能性が高い(K-Line解析でも車幅灯=0x25の1系統)。実配線調査時に確定させる
- ESP32-S3のLEDCは独立8ch → 全系統1台で駆動可。予約GPIO(6/7/8/9)では不足するため増設時に追加ピンを割り当てる(確定済みピンは変更禁止のまま)
- 恒久化は**系統ごと**に切替リレー(NC=純正/NO=自作)が必要
- ライブでの役割分担: 高速演出はフォグ(ハロゲン=ふわっと系)とハイビーム(LED=キレ系)が主役。ロービーム(HID)は「点けておく」ベース照明

## 設計原則(会話で確立したもの)

- ヒューズは負荷ではなく「下流の最細電線」を守る。容量は電線基準
- パワー線(B+/B−/M+/M−)は2.0sq・ネジ端子直結・ブレッドボード禁止
- GNDはバスバー一点集約。灯具の−はM−へ戻す(バスバー直結するとPWMが効かない)
- 純正系統との共存は現状「純正スイッチOFF+純正ヒューズ抜き」の暫定運用。恒久化は切替リレー
- ハロゲンは調光確実・ふわっと系の表現 / LEDはキレ系の表現。ライブでは使い分ける
